# 카피 쓰는 법 — 랜딩페이지가 죽는 이유는 대부분 디자인이 아니라 문장이다

## 1. 기능이 아니라 결과를 쓴다

방문자는 당신의 기술에 관심이 없다. 자기 문제가 사라지는지에만 관심이 있다.

| ✗ 기능 | ✓ 결과 |
|---|---|
| AI 기반 자동 매칭 알고리즘 | 팀원 구하는 데 3일 → 10분 |
| 클라우드 네이티브 아키텍처 | 사용자가 몰려도 안 터집니다 |
| 통합 대시보드 제공 | 흩어진 엑셀 5개를 한 화면에서 |

## 2. 한 문장에 한 가지만

`heading` 은 15자 내외, 길어도 25자. 쉼표로 두 문장을 이어붙이지 않는다.

## 3. 구체적인 숫자와 명사를 쓴다

- "빠르게" → "3초 안에"
- "많은 사용자" → "1,200명"
- "다양한 기능" → 기능 3개를 그냥 나열

## 4. 버튼 라벨은 동사 + 목적어

- ✗ 자세히 보기 / 더 알아보기 / 클릭 / 확인
- ✓ 무료로 시작하기 / 데모 신청하기 / 3분 만에 만들어보기

버튼 아래 `note` 로 망설임을 걷어낸다: "카드 등록 없이", "1분이면 끝나요", "언제든 해지 가능".

## 5. 없는 걸 지어내지 않는다 ★ 가장 중요

아직 출시 전인 서비스의 페이지에서 가장 흔한 사고다.

- 후기가 없으면 `testimonials` 섹션을 **뺀다**. 가짜 후기를 만들지 않는다.
- 도입 기업이 없으면 `logos` 를 **뺀다**.
- 아직 안 나온 실적을 숫자로 쓰지 않는다. 목표치라면 `label` 에 "목표"라고 밝힌다.
  (예: value `500명`, label `2026년 가입자 목표`)
- 실제 사람 이름·회사 로고를 허락 없이 넣지 않는다.

심사위원과 사용자는 이걸 귀신같이 알아본다. 빈 섹션을 빼는 게 채우는 것보다 훨씬 낫다.

## 6. 한국어 문장 톤

- 존댓말로 통일하되 "~하실 수 있습니다" 같은 늘어지는 어미를 줄이고 "~합니다 / ~하세요"로 짧게.
- 영어 약어를 처음 쓸 때만 괄호로 풀어준다.
- 느낌표는 페이지 전체에서 한두 개 이하.
- 이모지는 `features`/`problem` 의 `icon` 자리에서만. 문장 안에 섞지 않는다.

## 7. 쓰기 전에 답해야 할 5가지

이 답이 없으면 문장이 안 나온다. 모르면 사용자에게 묻는다.

1. 이건 **누구**를 위한 건가? (한 명의 구체적인 사람)
2. 그 사람이 지금 겪는 **문제**는 무엇인가?
3. 이걸 쓰면 **뭐가 달라지나**?
4. 왜 **다른 방법 말고 이것**인가?
5. 방문자가 여기서 할 **행동 딱 하나**는 무엇인가?
