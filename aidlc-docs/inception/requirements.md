# Requirements — 엔터테인먼트형 러닝 앱

## 1. Product Vision

사용자가 자신의 플레이리스트를 들으며 달리는 동안 **페이스, 시간, 거리, 러닝 모드, 랜덤 이벤트에 따라 음악과 사전 제작 TTS 나레이션이 변화**하여 러닝을 게임처럼 재미있게 만드는 모바일 앱을 개발한다.

### 핵심 가치
1. **익숙한 음악** — 사용자가 평소 듣는 플레이리스트 활용
2. **상황 반응형 러닝** — GPS 기반 페이스와 진행 상황에 따라 가이드 변경
3. **예측 불가능한 재미** — 랜덤 이벤트와 미션
4. **과몰입 경험** — 국가대표 모드처럼 사용자를 경기의 주인공으로 연출
5. **기록의 재미** — 음악과 이벤트가 러닝 퍼포먼스에 미친 영향 기록

## 2. Primary User Journey

1. 앱 실행
2. 러닝용 플레이리스트 선택
3. 거리/시간/목표 페이스 설정
4. 러닝 모드 선택
5. 러닝 시작
6. GPS로 시간, 거리, 현재/평균 페이스 계산
7. 이벤트 조건 또는 일정 주기에 따라 TTS 가이드 재생
8. 모드/페이스/랜덤 이벤트에 따라 다음 음악 카테고리 변경
9. 러닝 종료 후 기록·음악·이벤트 결과 확인

# 3. Functional Requirements

## FR-01. 플레이리스트 선택
**User Story:** 사용자는 평소 좋아하는 음악을 들으며 러닝하고 싶다.

- **WHEN** 사용자가 러닝 준비 화면에 진입하면  
  **THE SYSTEM SHALL** 연결된 음악 서비스에서 플레이리스트를 선택할 수 있게 한다.
- **WHEN** 사용자가 플레이리스트를 선택하면  
  **THE SYSTEM SHALL** 해당 플레이리스트를 현재 러닝 세션에 저장한다.
- **WHEN** 러닝이 시작되면  
  **THE SYSTEM SHALL** 선택한 플레이리스트 재생을 시작한다.
- **WHEN** 외부 음악 서비스 연동에 실패하면  
  **THE SYSTEM SHALL** 오류를 알리고 재연결 또는 대체 방식을 제공한다.

### MVP
- 플레이리스트 1개 선택
- 순차/셔플 재생

## FR-02. 러닝 목표 설정
**User Story:** 사용자는 오늘 달릴 거리와 목표를 미리 정하고 싶다.

- **WHEN** 사용자가 러닝을 준비하면  
  **THE SYSTEM SHALL** 목표 거리, 목표 시간, 목표 페이스를 설정할 수 있게 한다.
- **WHEN** 목표가 저장되면  
  **THE SYSTEM SHALL** 러닝 중 현재 기록과 목표를 비교한다.

### Preset
- 거리: 3km / 5km / 10km / 직접 입력
- 시간: 30분 / 60분 / 직접 입력
- 목표 페이스: min/km

## FR-03. 러닝 모드 선택
**MVP Modes**
1. 기본 모드 — 최소 기록 안내 + 내 플레이리스트
2. 마라톤 모드 — 목표 페이스 유지와 거리 진행 중심
3. 인터벌 모드 — 빠른 구간/회복 구간 반복
4. 국가대표 모드 — 스포츠 중계 스타일 나레이션 + 가상 경쟁

- **WHEN** 러닝 전 모드를 선택하면  
  **THE SYSTEM SHALL** 해당 모드의 이벤트 규칙, TTS 세트, 음악 전환 규칙을 적용한다.

## FR-04. GPS 기반 러닝 기록 측정
- **WHEN** 러닝이 시작되면  
  **THE SYSTEM SHALL** 위치 정보를 이용해 경과 시간, 거리, 현재 페이스, 평균 페이스를 계산한다.
- **WHEN** GPS 순간값이 비정상적으로 튀면  
  **THE SYSTEM SHALL** 이동 평균 또는 동등한 보정 로직으로 변동을 완화한다.
- **WHEN** 위치 정확도가 낮으면  
  **THE SYSTEM SHALL** 잘못된 이벤트 발생을 최소화한다.
- **WHEN** 사용자가 일시정지하면  
  **THE SYSTEM SHALL** 시간/거리 계산과 속도 기반 이벤트를 중지한다.

## FR-05. 주기적 러닝 가이드
- **WHEN** 설정된 시간이 경과하거나 특정 거리를 통과하면  
  **THE SYSTEM SHALL** 상황에 맞는 TTS를 재생한다.
- **WHEN** 5분 안내 이벤트가 발생하면  
  **THE SYSTEM SHALL** "5분째 달리고 있습니다. 현재 페이스는 OO입니다." 형태로 안내할 수 있어야 한다.
- **WHEN** TTS가 재생되면  
  **THE SYSTEM SHALL** 음악 볼륨을 일시적으로 낮추고 종료 후 복구할 수 있어야 한다.

## FR-06. 사전 제작 TTS 라이브러리
- **WHEN** TTS 세트가 등록되면  
  **THE SYSTEM SHALL** `mode`, `eventType`, `tone`, `priority` 등으로 분류한다.
- **WHEN** 이벤트가 발생하면  
  **THE SYSTEM SHALL** 대응 TTS 후보군 중 하나를 선택한다.
- **WHEN** 같은 TTS가 최근 재생되었다면  
  **THE SYSTEM SHALL** 반복 빈도를 제한한다.

### Categories
- 페이스 안내
- 거리 통과
- 격려
- 라이벌
- 마지막 스퍼트
- 웃긴 상황
- 성공/실패
- 완주

## FR-07. 랜덤 이벤트
- **WHEN** 이벤트 체크 주기가 도래하면  
  **THE SYSTEM SHALL** 설정된 확률과 쿨다운을 기준으로 발생 여부를 결정한다.
- **WHEN** 이벤트가 발생하면  
  **THE SYSTEM SHALL** 해당 TTS와 음악 행동을 실행한다.
- **WHEN** 동일 이벤트가 최근 발생했다면  
  **THE SYSTEM SHALL** 일정 시간 중복 발생을 억제한다.

### Examples
- `IDEAL_TYPE_APPEARED` — "앞에 이상형이 나타났습니다." → 사랑 노래
- `RIVAL_CHASING` — "뒤에서 라이벌이 따라옵니다." → high-energy 음악
- `PACE_DROP` — 페이스 하락 → 격려 + 빠른 템포 후보
- `GOOD_RHYTHM` — 페이스 유지 성공 → 긍정 TTS
- `RARE_EVENT` — 낮은 확률 특별 이벤트

> 사람/상황은 실제 영상 인식이 아니라 **게임적 가상 이벤트**로 처리한다.

## FR-08. 상황 기반 음악 전환
- **WHEN** 일반 상태이면  
  **THE SYSTEM SHALL** 사용자의 플레이리스트를 기본 재생한다.
- **WHEN** 속도를 올려야 하는 이벤트가 발생하면  
  **THE SYSTEM SHALL** `high-energy` 또는 빠른 BPM 곡을 우선한다.
- **WHEN** 회복 구간이면  
  **THE SYSTEM SHALL** `recovery` 음악을 우선한다.
- **WHEN** 사랑 관련 이벤트가 발생하면  
  **THE SYSTEM SHALL** `love` 태그 음악을 우선한다.
- **WHEN** 음악 카테고리가 변경되더라도  
  **THE SYSTEM SHALL** 가능한 경우 현재 곡을 즉시 끊지 않고 다음 곡부터 반영한다.

### MVP Music Tags
`normal`, `high-energy`, `recovery`, `love`, `dramatic`, `favorite`

## FR-09. 마라톤 모드
- 내 플레이리스트 기본 재생
- 일정 거리/시간마다 기록 안내
- 목표 페이스 대비 차이 안내
- 후반부 신나는 음악/격려 증가
- 마지막 구간 Final Boost

## FR-10. 인터벌 모드
- 빠른 구간/회복 구간 시간 및 세트 수 설정
- 빠른 구간 → high-energy 음악 + TTS
- 회복 구간 → recovery 음악 + TTS
- 세트 종료 시 완료 안내

## FR-11. 국가대표 모드
- 경기 중계 스타일 TTS
- 거리/페이스/마지막 구간 상황별 중계
- 목표 페이스 기반 Ghost Runner
- 가상 순위 또는 앞섬/뒤처짐 이벤트

## FR-12. 러닝 미션
### MVP Missions
- `SPEED_BOOST` — 일정 시간 속도 올리기
- `PACE_KEEP` — 일정 시간 목표 범위 유지
- `LAST_SONG` — 현재 곡이 끝날 때까지 달리기
- `ONE_MORE_SONG` — 종료 시 한 곡 더 도전

- **WHEN** 미션이 시작되면 목표와 종료 조건을 안내한다.
- **WHEN** 조건을 만족하면 성공을 기록하고 성공 TTS를 재생한다.
- **WHEN** 실패하더라도 러닝 자체는 계속할 수 있다.

## FR-13. 페이스 콤보
- 목표 페이스 허용 범위 유지 시간을 누적
- 범위 이탈 시 종료/감소
- 특정 콤보 기준 달성 시 보상 피드백

## FR-14. 러닝 종료 리포트
러닝 종료 후 다음 정보를 표시한다.
- 거리
- 시간
- 평균 페이스
- 최고 페이스
- 사용 모드
- 이벤트 발생 횟수/결과
- 미션 결과
- 최고 콤보
- 가상 라이벌 결과
- 음악별 퍼포먼스(가능한 경우)

## FR-15. 곡별 러닝 퍼포먼스
- 곡 재생 구간의 평균 페이스 계산
- 기록이 충분하면 "나를 가장 빠르게 뛰게 만드는 곡 TOP N" 제공
- MVP에서는 선택 기능

# 4. AI Agent Requirements

## AR-01. Agent 역할
AI Agent는 저수준 센서 계산을 담당하지 않는다.

### Agent 담당 후보
- 러닝 전 추천 모드/세션 생성
- 여러 이벤트 후보 중 상황에 맞는 조합 추천
- 러닝 종료 후 재미있는 한 줄 요약
- 장기적으로 사용자 반응 기반 개인화

### 일반 코드 담당
- GPS 수집
- 거리/페이스 계산
- 인터벌 타이머
- 난수/확률 이벤트
- 미션 성공/실패 판정
- 안전 제한
- TTS 파일 재생

# 5. Non-Functional Requirements

## NFR-01. 반응성
- 러닝 수치는 적절한 주기로 갱신한다.
- 주요 TTS는 사전 생성 및 로컬 캐싱을 우선한다.

## NFR-02. 배터리
- GPS 정확도와 업데이트 주기를 러닝 품질/배터리 사이에서 조정한다.

## NFR-03. 네트워크
- 네트워크가 끊겨도 시간/거리 기록은 가능한 범위에서 지속한다.
- 캐싱된 TTS는 오프라인에서도 재생 가능해야 한다.

## NFR-04. 개인정보
- 위치 정보는 러닝 기능에 필요한 범위에서만 사용한다.
- 음악 서비스 토큰은 안전하게 저장하며 로그에 노출하지 않는다.

## NFR-05. 안전
- GPS 정확도가 낮거나 일시정지 상태에서는 속도 상승 미션을 생성하지 않는다.
- 사용자는 언제든 음성 가이드/랜덤 이벤트를 끌 수 있다.

## NFR-06. 테스트 가능성
- Pace, 이벤트, 미션, 모드 로직은 UI와 분리하여 단위 테스트 가능해야 한다.

# 6. MVP Scope

## 반드시 구현
- 플레이리스트 선택
- 러닝 목표 설정
- 기본/마라톤/인터벌/국가대표 모드
- GPS 기반 시간/거리/페이스
- 사전 제작 TTS
- 일정 시간/거리 안내
- 랜덤 이벤트
- 이벤트에 따른 음악 카테고리 변화
- 러닝 종료 리포트

## 가능하면 구현
- Ghost Runner
- Pace Combo
- 랜덤 미션
- 한 곡만 더
- 곡별 퍼포먼스

## 이후 확장
- 사용자 레벨/칭호
- 친구 경쟁
- 실시간 멀티플레이
- 스마트워치/심박수/케이던스
- 개인화 Pace-BPM 추천

# 9. Success Criteria
- 5km 러닝 세션 생성/시작 가능
- 거리/페이스 자동 계산
- 5분/1km 시점 TTS 정상 재생
- 최소 3종 랜덤 이벤트
- 이벤트에 따른 음악 규칙 변화
- 4개 모드가 서로 다른 경험 제공
- 종료 후 기록/이벤트 리포트 확인
